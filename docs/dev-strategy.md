# 開発戦略

## 背景

AI により生産・模倣コストは0となる。

### 価値↑

- ビジネス感覚：ボトルネックは「何を作るか」
- 意思決定（＝責任）

### 価値↓

- アウトプット力
- 実装力

## 指針

価値↑の力を伸ばす。

### 1. 意思決定に注力しよう

| 注力 | AIに委譲 |
|---|---|
| テストケース作成 | |
| 核となるテスト実装 | 定型的なテスト実装 |
| 設計判断「いつ複雑化（↔︎単純化）するか」 | 実装 |
| リファクタリング方針決定 | リファクタリング |
| ADR化判断 | ADR作成 |

各意思決定について AI と議論を重ねてブラッシュアップする。  
検証結果や公式ドキュメントの引用を、意思決定の根拠とする。

### 2. 説明できる PR のみマージしよう

AI 出力の責任を引き受ける。  
自分の言葉で PR の妥当性を説明する。

### 3. 知らないことはその場で調べよう

AI が出力/実装する「自分の知らないこと」は、その場で調べてドキュメント化する。

### 4. 自動化をデフォルトにしよう

AI をフル活用して自動化を試みる。

### 5. 長期運用に耐えるシステムを設計しよう

例えば以下を考慮する。
- アラート検知の仕組み
- 定期バックアップ
- 依存する外部サービス障害時の挙動

有料化して、責任ある運用を行う。

### 6. 能動的にフィードバックを獲得しよう

プロダクトは早期にリリースして、家族・友人にレビューを募る。  
最初の利用者獲得に注力する。

### 7. 月 1 振り返りをしよう

プロダクト利用者を増やすための調査/分析を行う。  
as-is, to-be をまとめる。  
ADRを振り返る。

### 8. 先人に学ぼう

偉大な先人の書籍から体系的に、コードから個別的に学ぶ。

[基礎]

OSやネットワーク、データベースの仕組みなど普遍的な基礎を学び続ける。

[応用]

1. 開発する
2. 困り始める
3. 改善を考える
4. 書籍/コードを読む（解決策の選択肢を増やす）
5. 適用して効果を検証する
